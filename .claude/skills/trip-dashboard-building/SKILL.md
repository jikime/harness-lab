# Trip Dashboard Building

## 역할

가족 여행 준비 하네스의 마지막 실행 단계 매뉴얼이다. 이미 확정된 데이터를 정해진 형식으로 옮기는 조립 작업이며, 새로운 판단은 하지 않는다.

## 사용 조건

- 사용해야 하는 경우: `family-trip-prep-orchestrator`가 대시보드 조립 단계를 위임했을 때, 사용자가 "대시보드만 다시 만들어줘"처럼 부분 재실행을 요청했을 때.
- 사용하지 말아야 하는 경우: 조사, 일정 설계, 체크리스트 검토처럼 판단이 필요한 단계.

## 입력

- `artifacts/family-trip-prep/01-research-notes.md`
- `artifacts/family-trip-prep/02-itinerary-draft.md`
- `artifacts/family-trip-prep/03-checklist-review.md`

## 절차

1. 세 입력 파일을 읽고 각 섹션에 필요한 데이터를 추출한다.
2. 예산 합계·항목이 `02-itinerary-draft.md`와 정확히 일치하는지 옮기기 전에 대조한다. 불일치를 발견하면 임의로 고치지 말고 오케스트레이터에게 차단을 보고한다.
3. TailwindCSS(CDN)로 일정 카드, 예산 표, 체크리스트, 항공권/숙소 후보 카드를 배치한다.
4. Chart.js(CDN)로 예산 항목별 비중 차트를 만들고, 차트 데이터가 예산 내역표 숫자와 같은지 다시 확인한다.
5. 항공권/숙소 후보와 결제가 필요한 모든 항목에 "사람 승인 필요" 배지를 눈에 띄게 표시한다.
6. 모바일 폭(360px 기준)에서 텍스트 겹침, 표 넘침, 차트 깨짐이 없는지 확인한다.

## 출력

- 저장 위치: `artifacts/family-trip-prep/dashboard.html`
- 완료 기준: 대시보드의 모든 숫자가 원본 파일과 정확히 일치하고, 예약·결제 항목에 "사람 승인 필요" 배지가 있으며, 모바일 폭에서 레이아웃이 깨지지 않는다.

## 품질 기준

- 통과 기준: 숫자 일치, 승인 배지 존재, 모바일 확인 완료.
- 사람 승인 조건: 항공권/숙소 예약, 결제와 관련된 모든 항목은 대시보드 완성만으로 "사용 가능"이 되지 않는다. 실제 예약·결제는 사람이 대시보드를 보고 직접 진행한다.
- 실패 시 처리: 입력 파일 간 숫자가 다르면 조립을 멈추고 오케스트레이터에게 보고한다. 추측으로 숫자를 맞추지 않는다.

## 예시

Should trigger:
- "다 됐으니 대시보드로 정리해줘"
- "대시보드만 다시 만들어줘"

Should not trigger:
- "예산 다시 배분해줘" (itinerary-planning의 책임)
- "체크리스트 항목 추가해줘" (trip-checklist-review의 책임)

Ask before proceeding:
- 입력 파일 중 하나라도 없는 상태에서 대시보드부터 만들어 달라는 요청
